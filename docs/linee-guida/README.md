# Linee guida di Journey Planner (Faraway)

Queste pagine dicono che cosa è l'app e come si lavora: per chi scrive codice, per chi disegna una schermata, per un agente che apre la repo per la prima volta. Si leggono in quest'ordine.

| File | Che cosa contiene |
| --- | --- |
| [01-prodotto.md](01-prodotto.md) | A che cosa serve l'app, per chi, le sezioni, i concetti, la voce |
| [02-regole-generali.md](02-regole-generali.md) | Come si lavora sulla repo e le regole di interfaccia valide ovunque: navigazione, conferme, caricamenti, offline |
| [03-modali-e-moduli.md](03-modali-e-moduli.md) | Fogli dal basso, modali al centro, moduli: struttura, gruppi, campi, testi |
| [04-accessibilita.md](04-accessibilita.md) | Le regole WCAG 2.2 AA applicate all'app, con i controlli da fare |
| [05-css-e-stile.md](05-css-e-stile.md) | Token, temi chiaro e scuro, spaziature, tipografia, componenti, cosa non scrivere nel CSS |

Il riferimento visivo è il design system «Faraway Definitivo» (artifact su claude.ai). Se una regola qui e il design system non coincidono, vale l'app com'è oggi: si aggiorna il design system, non il contrario.

Quando una regola cambia, si aggiorna il file giusto nello stesso commit della modifica al codice.
